# 범주

이 파일은 모든 범주와 순서, 영향도, 설명을 정의한다.
괄호 안의 범주 ID는 규칙을 묶는 데 사용하는 파일명 접두사다.

---

## 1. 아키텍처 (arch)

**영향도:** CRITICAL
**설명:** 올바른 모듈 구성과 의존성 관리는 유지보수하기 쉬운 NestJS 애플리케이션의 토대다. 순환 의존성과 거대 서비스는 아키텍처를 해치는 가장 큰 원인이다.

## 2. 의존성 주입 (di)

**영향도:** CRITICAL
**설명:** NestJS의 IoC 컨테이너는 강력하지만 잘못 사용할 수 있다. 테스트 가능한 코드를 작성하려면 스코프, 주입 토큰, 올바른 패턴을 이해해야 한다.

## 3. 오류 처리 (error)

**영향도:** HIGH
**설명:** 일관된 오류 처리는 디버깅, 사용자 경험, API 신뢰성을 높인다. 중앙화된 예외 필터는 통일된 오류 응답을 보장한다.

## 4. 보안 (security)

**영향도:** HIGH
**설명:** 보안 취약점은 치명적인 결과를 낳을 수 있다. 입력 검증, 인증, 인가, 데이터 보호는 필수다.

## 5. 성능 (perf)

**영향도:** HIGH
**설명:** 요청 처리, 캐싱, 데이터베이스 쿼리 최적화는 애플리케이션의 응답성과 확장성에 직접적인 영향을 준다.

## 6. 테스트 (test)

**영향도:** MEDIUM-HIGH
**설명:** 충분히 테스트한 애플리케이션은 더 안정적이다. NestJS 테스트 도구는 단위 테스트와 E2E 테스트로 폭넓게 검증할 수 있도록 돕는다.

## 7. 데이터베이스와 ORM (db)

**영향도:** MEDIUM-HIGH
**설명:** 적절한 데이터베이스 접근 패턴, 트랜잭션, 쿼리 최적화는 데이터를 많이 다루는 애플리케이션에서 중요하다.

## 8. API 설계 (api)

**영향도:** MEDIUM
**설명:** RESTful 관례, 버전 관리, DTO, 일관된 응답 형식은 API의 사용성과 유지보수성을 높인다.

## 9. 마이크로서비스 (micro)

**영향도:** MEDIUM
**설명:** 분산 시스템을 구축하려면 메시지 패턴, 상태 검사, 서비스 간 통신을 이해해야 한다.

## 10. DevOps와 배포 (devops)

**영향도:** LOW-MEDIUM
**설명:** 설정 관리, 구조화된 로깅, 안전한 종료는 운영 준비와 무중단 배포를 뒷받침한다.
