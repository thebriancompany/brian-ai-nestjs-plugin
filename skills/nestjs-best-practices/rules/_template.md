## 구체적인 행동을 나타내는 제목

이 파일은 규칙 작성용 템플릿이며 적용 규칙 40개에는 포함하지 않는다. 실제 규칙에서는 이 안내와 작성 기준을 제거하고 해당 주제의 내용으로 대체한다.

적용할 조건과 해결할 실패를 설명한다. 작은 구현에도 패턴을 일괄 강제하지 말고 적용하지 않아도 되는 경우를 짧게 밝힌다. 수치나 성능 개선율은 측정 근거가 있을 때만 쓴다.

**잘못된 예 (재현 가능한 실패 조건):**

해당 실패를 보여 주는 최소 코드를 넣는다. 정상적인 설계 대안을 취향만으로 잘못된 예라고 부르지 않는다.

**올바른 예 (같은 조건에서 실패를 해결하는 구현):**

설명한 실패를 실제로 해결하는 코드를 넣는다. 필요한 패키지 버전·어댑터·주입 토큰·모듈 등록을 명시한다. 대안은 별도 코드 블록으로 구분한다. 핵심 메서드를 빈 본문이나 의미가 불명확한 헬퍼로 남기지 않는다. 앱이 구현해야 할 도메인 계약은 입력·출력·실패 의미를 설명한다.

코드 밖에서 보장 범위와 남은 통합 조건을 짚는다. 관련 규칙에 같은 구현이 있다면 복제하지 말고 연결한다. 마지막에는 적용한 버전에 맞는 공식 문서나 소스를 링크한다.

### 작성 후 검증

- 메타데이터 제목과 본문 제목, 파일명·분류·SKILL.md 링크를 맞춘다.
- 개선 예제에서 새로 소개한 API의 타입·주입·수명과 정상·실패 동작을 확인한다.
- 보안·동시성·종료 같은 경계는 실제 라이브러리와 동작 테스트로 검증한다. 텍스트 검색만 통과한 결과를 동작 검증으로 보고하지 않는다.
- 도메인 fixture나 mock으로 보완한 부분과 실제 DB·브로커 등 검증하지 않은 부분을 구분한다.
- 관련 규칙과 함께 사용했을 때 등록 순서·단위·데이터 계약이 충돌하지 않는지 확인한다.
